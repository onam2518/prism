## 관리자 메뉴 소실 최종 해소 + 배포 체험 (7/8)

  만료 후 관리자 판정만 조용히 실패(읽기 화면은 정상이라 로그인된 것처럼 보임).
  "로그아웃 후 재로그인하면 생김"이 결정적 단서. refresh token 저장 · 부팅 선갱신 ·
  45분 주기 연장 · /admin 은 만료를 401 로 구분 · 401 시 1회 자동 갱신 후 재시도 ·
  갱신 실패 시 만료 안내+로그인 화면. 배포 후 각자 **1회 재로그인** 필요(이후 자동 연장).
- **새 버전 배포 감지 배너**(#47): 서버 부팅 ID 를 SSE 접속 인사(hello)와 /config 로 노출.
  배포 = SSE 재연결 = 부팅 ID 변화 → 하단 배너 "새 버전이 배포되었습니다" + [새로고침] 단일
  유도(분기 없음). 페이지의 벤더 js/css 는 ?v=부팅ID 캐시버스터라 일반 새로고침만으로 새
  스크립트 확정 로드(강력 새로고침 불필요 · 세션 만료 상태면 자연스럽게 로그인 화면).

## 성능 (실측 기반 3차 · #48~#50)

- 사전 실측: 첫 로드 4.7MB(폰트 3.8MB + 텍스트 0.94MB · 압축 0 · 캐시 헤더 0) ·
  API /config 862ms·/arena 734ms(콜마다 새 TLS 도쿄→서울 + 인증 요청마다 팀 조회 1콜).
- 1차 전송(#48): _send gzip 협상(텍스트 1KB↑) · 벤더 캐시(?v= 불변 1년·폰트 30일·기타 1시간 ·
  HTML 은 no-store 유지로 버전 감지와 정합) · supastore keep-alive(http.client 스레드별 재사용 ·
  라이브 계약 22종 통과) · team_of 60s 캐시(/reviewer 시 무효화).
- 2차 자산(#49): Tailwind Play CDN 런타임(397KB + 접속마다 브라우저 JIT) → 사전 빌드
  tw.css 8.8KB. 설정 scripts/tailwind.config.js(인라인 config 1:1) · 재생성
  scripts/build_tailwind.sh(**유틸 클래스 추가·변경 시 실행 후 tw.css 커밋**) · 캐스케이드
  위치 보존(app.css 뒤) · 라이트/다크 실렌더 검증. GmarketSans woff 3종 → woff2(1.8→1.23MB ·
  구 woff 제거 · DMG 번들 동일 절감).
- 3차 폰트(#50): Pretendard 2단 서브셋 · 서브셋 644KB(공식 KS X 1001 커버리지 3,728자 ·
  정적 subset 배포의 cmap 과 동일 글리프 · pyftsubset · wght 가변 축 유지) = 일반 사용 유일
  전송, 풀 2MB 는 서브셋 밖 희귀 글자 등장 시에만 unicode-range 로 추가 로드(글자 누락 없음).
  실브라우저: 홈 로드 시 서브셋만 요청 확인.
- **결과**: 첫 방문 4.7MB → **약 1.6MB** · 재방문 **54KB**(벤더 전량 캐시) ·
  /config 862→약 220ms · /arena 734→약 140ms · /raw 164KB→54KB.
