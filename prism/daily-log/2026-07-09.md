게임 점수를 검수 데이터 삭제와 분리한 뒤, **검수 특화 모바일 페이지(/m)** 를

## 개선 배치 A~G 마감 (오전 · #60~#63 머지)

- 어제 만든 E(배포-배치 충돌 가드 + 실행 큐 영속화 #60) · F(인증 만료 통일 #61) ·
  G(E2E 스모크 #62) · 데일리로그 2부(#63) 머지·배포. 이후 모든 배포가 E 의 가드
  (배치 실행 중이면 최대 10분 대기)와 G 의 스모크 게이트를 거친다 — #68 배포에서 첫 실작동 확인.

## 게임 점수-검수 데이터 분리 (#68)

- 발단 질문: "검수 데이터 삭제하면 게임 진척도는?" → 구조 진단: 점수·레벨은 저장값이
  아니라 파생 계산(검수 10 + 교정 25 + 구조화 5 + 합의 5 + 골드 10 × 품질 배율 + 보너스)
  이라 **피드백 삭제 = 진척도 소멸**, 단 배지·미션 보너스·골드·교정 로그는 별도 원천이라 잔존.
- 분리(사용자 제안): 피드백 전체 삭제 직전 **사라질 몫만 events 적립(score_carry)** 으로
  전환 — 잔존 원천(patch_log 5점·gold 10점·기존 보너스)에서 재계산될 몫은 빼서 이중 적립
  방지 → 삭제 전후 총점 동일. 삭제 확인문에 "점수·레벨 보존" 명시.
- **게임 점수 초기화 버튼**(시스템 설정 · 운영 관리자): 현재 총점만큼 음수 오프셋
  (score_reset) 적립 = 검수 데이터·배지·정답셋 불변으로 0부터 재시작(시즌 리셋 용도).
- 표시 정합: 보너스만 남은 검수자도 리더보드 유지(삭제 후 소실 착시 방지) · 점수/주간
  점수 0 하한(음수 레벨 방지) · leaderboard 에 reviewer_id 동반(양 스토어).
- 회귀 3건(총점 불변 · 초기화 후 재적립 · 음수 하한).
