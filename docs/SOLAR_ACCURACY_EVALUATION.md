# Solar Pro 4 v4: 정확성과 맥락 보존의 공동 평가

기준일 2026-10-28. 후보 버전 `solar-accuracy-2026-10-28-v4`.

## 변경 범위

기존 계약 규칙·전체 사전·예시를 보존하고 출력 전 검사를 필드별로 보강한다.
리드문에서는 주체·대상·수치·단위·날짜·부정·확정 여부·인용 주체를 대조하며,
오류를 피하려고 중요한 사실을 삭제하지 않도록 명시한다. 엔티티와 라벨은
근거 없는 추가와 핵심 누락을 함께 검사한다. 카테고리는 `tier1`, `tier2`를 그대로 쓰게 한다.
검토 과정은 출력하지 않고 기존 JSON 계약을 따른다. 추론 API 옵션은 비교를 위해
기존과 같은 `reasoning_effort=none`이다. 별도의 추론 모드를 켠 실험은 아니다.

`prism/solar_accuracy.py`는 명시적 실험 빌더다. 운영 기본 프롬프트는 변경하지 않는다.
이전 v3와 그 평가 기록도 보존한다.

## 평가 축

| 축 | 계산 | 한계 |
|---|---|---|
| 형식 유효성 | 문서별 4개 호출 모두 JSON·키·사전 값 검사 통과 | 의미 정확성과 별개 |
| 원문 사실성 | 산출문의 원자 주장 중 원문이 지지하는 비율 | 같은 모델의 잠정 판정 |
| 정답 정보 보존 | 원문이 지지하는 정답 주장 중 산출문이 완전히 전달한 비율 | 정답에 없는 핵심까지 평가하지 않음 |
| 라벨 정확성 | 엔티티·인텐트 P/R/F1, 카테고리 정확·계층 F1 | 정답 주석 품질·범위에 의존 |
| 맥락 유사도 | 정답과 산출문의 passage 임베딩 코사인 | 정확도·확률로 해석 불가 |

핵심 정보 누락을 별도로 측정해 짧고 사실적인 문장이 무조건 높은 평가를 받는 것을 막는다.
정답은 두 산출문을 보기 전에 문서당 한 번 원자 주장으로 분해하고 원문과 대조한다.
원문이 지지하지 않는 정답 주장은 제외 수와 판정 근거를 남긴다. 이 판정만으로
정답 DB를 수정하거나 주석 오류로 확정하지 않는다. 양쪽 후보에 동일한 주장을 적용한다.
평가자가 주장을 누락하거나 중복 판정한 경우, 존재하지 않는 근거 ID를 낸 경우는 실패다.

탐색용 `review_all_clear`는 4개 출력 형식이 유효하고, 비어 있지 않은 리드문의
원문 지지율과 정답 주장 보존율이 모두 1일 때만 1이다. 형식 실패·빈 리드문은 0,
평가 실패는 미측정으로 둔다. 엔티티·라벨의 의미 정확성은 이 진단값에 포함하지 않는다.
이 엄격한 진단은 운영 승인선이나 사람 기준 정확도가 아니다. 전체 표본 수와 유효 쌍을
반드시 함께 보고하며, 사실성·보존율·라벨 F1·코사인을 하나의 가중 점수로 합치지 않는다.

## 실험과 채택 검토

v3에서 이미 사용한 24건을 v4 개발 평가로 사용한다. 이전 평가 미사용 35건은
최종 검증용으로 남기고 이번 개발 점수에 포함하지 않는다. 같은 개발 표본을
재사용했으므로 v4 결과로 일반화 성능을 확정할 수 없다.

생성 조건은 두 변형 모두 Solar Pro 4 260806, temperature=0, JSON object,
최대 2,048토큰, 재시도 없음이다. 별도 사실·보존 평가 호출은 최대 4,096토큰이다.
프롬프트와 데이터 해시, 실제 응답 모델명, 모든 응답·실패·사용량을 기록한다.
이전과 같은 문서 대응 부트스트랩 2,000회·95% 구간으로 비교한다.

개발 결과를 보기 전에 정한 탐색용 후속 검토 조건:

- 후보 형식 실패 0건.
- 정답 주장 보존율과 원문 지지율의 표본평균이 기준보다 낮아지지 않음.
- 엔티티 F1·인텐트 F1·카테고리 계층 F1의 표본평균이 기준보다 낮아지지 않음.
- 비교 지표의 결측 쌍 0건.

이 조건은 추가 검증에 들어갈 후보를 거르는 보수적인 개발 규칙이다. 통계적 비열등성
검정이나 운영 성능 보증이 아니다. 충족해도 자동 승격하지 않으며, 미사용 표본과
사람의 오류 유형 검수를 거쳐야 한다. 실패하면 이유와 원응답을 남기고 미사용 표본을 보존한다.

## 연구 기반과 실제 구현의 차이

[FActScore, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.741/)는
원자 사실 중 지식 근거가 지지하는 비율로 사실 정밀도를 평가한다. 사실 정밀도만으로
정보 누락을 충분히 평가할 수 없다는 점을 설계에 반영했다.

[QAEval, TACL 2021](https://aclanthology.org/2021.tacl-1.47/)는 정답의 정보를
질의응답으로 표현해 후보가 얼마나 보존했는지 평가한다. 이번 구현은 QA 모델을 실행하는
QAEval 재현이 아니다. 정답을 고정된 주장으로 분해하고 같은 주장의 전달 여부를 묻는
실험용 AI 판정이다. FActScore의 공식 구현이나 벤치마크 점수와도 직접 비교할 수 없다.

맥락 유사도의 연구·공식 기술 블로그는 `SOLAR_CONTEXT_EVALUATION.md`에 정리했다.
같은 Solar가 생성과 평가를 수행하므로 공통 오류와 선호 편향이 남는다. 원문·정답·
산출문을 바탕으로 사람이 주체/수치/부정/상태/누락/라벨 오류를 판정하고 자동 평가와
대조해야 사람 기준 정확도를 얻을 수 있다. 이번에 사람 간 합의도나 평가자 정확도를
측정한 것으로 보고하지 않는다.

## 재현

```sh
python3 scripts/evaluate_solar_context.py --candidate accuracy \
  --golden /path/to/dev24.jsonl --output /path/to/new-run --limit 24 --live --judge
python3 scripts/evaluate_solar_accuracy.py --folder /path/to/new-run --live
```

키는 `UPSTAGE_API_KEY` 환경변수로 전달한다. 두 번째 단계는 저장된 생성 결과를
평가하며 생성 모델을 다시 실행하지 않는다. 동일 경로 덮어쓰기는 거부한다.
