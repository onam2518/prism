# Prism Admin · IA & 풀스펙 로드맵

DNM 맥락형 콘텐츠/사용자 메타 체계(Confluence 13)를 **생성하고 수행하는 어드민 콘솔**로서의 Prism.
이 문서는 (1) 정보 구조(IA)와 (2) 현재→풀스펙 로드맵을 정리한다. 구조도: `docs/ia-admin.png`.

기준 문서 · 13(프로젝트 기획) / 131(콘텐츠 메타) / 1311(품질) / 1312(아이템) / 132(토픽) / 133(사용자) / 134·0021(이미지 PoC).

## 1. Information Architecture

### 1.1 모듈 트리 (좌측 내비)

```
Prism Admin
├─ 0. 대시보드 · KPI                  ⬜  유통률 G/R · 처리량 · 품질(ROUGE) · 강도 분포
├─ 1. 인입 · 적용 대상                 🟣  ITEM TYPE 정책 · 출처 분류 · 인입 큐
├─ 2. 품질 메타                        🟣  1차 법령 ∥ 2차 품질 → 유통 판정
├─ 3. 아이템 메타                      ✅  리드문 · 엔티티 · 인텐트 · 콘텐츠 카테고리
├─ 4. 토픽 관리                        🟣  엔티티형 · 사건형 · 조건형
├─ 5. 사용자 메타                      ⬜  소비 형태 · 강도 · 선호
├─ 6. 사전 · 매핑                      🟣  인텐트 · 콘텐츠 카테고리 · 트롬/IAB
├─ 7. 모델 · 라우팅                    ✅  텍스트/이미지 슬롯 · Solar/BizRouter/Timely
├─ 8. 검증 · 평가                      🟣  Groundedness · ROUGE · 정확도 게이트
└─ 9. 실행 · 리포트                    ✅  단건/일괄 · 통합 리포트 · CSV/JSON
```

### 1.2 화면별 구성

- **0. 대시보드** · 운영 현황 카드(유통 가능률, 처리량, 인텐트/강도 분포), 품질 지표 추이, 세그먼트 모니터링. *현재 엑셀 배치 집계 인포그래픽이 부분 제공.*
- **1. 인입 · 적용 대상** · ITEM TYPE별 처리 정책(텍스트형 정상 분류 / 이미지형 GREEN+캡션 / 영상·SNS·묶음·데이터형 일괄·제외), 콘텐츠 출처 분류(PGC·UGC·AIGC·AIEC), 인입 큐·배치 업로드.
- **2. 품질 메타** · 1차 법령 필터(법령 세트, A·B·C 스코어링, RED 임계) ∥ 2차 품질 필터(품질 메타 정의, status 기준, 프롬프트 가이드, 테스트셋) → status 종합 유통 판정(G/R).
- **3. 아이템 메타** · 리드문 생성 → 엔티티(단일명사 1~3, 인용/주체 규칙, 정제) → 인텐트(사전값) → 콘텐츠 카테고리(N개, IAB Tier1/2) → 토픽·토픽 카테고리. 이미지형은 시각 이해 경유.
- **4. 토픽 관리** · 엔티티형(1321)·사건형(1322, 대표 1+관련 N, 중복 제거)·조건형(1323, 관심사×소비 방식) 빌더와 클러스터 운영.
- **5. 사용자 메타** · TIARA 로그 입력 → 세션화 → 소비 형태(FORM)·소비 강도(저·중·고)·선호(인텐트·엔티티·카테고리). 콘텐츠 측과 동일 사전·척도.
- **6. 사전 · 매핑** · 인텐트 사전(콘텐츠/사용자 공용), 콘텐츠 카테고리 사전(자사 21 Tier1 + Custom Tier2), 트롬↔카테고리·IAB v3.0 매핑.
- **7. 모델 · 라우팅** · 텍스트/이미지 슬롯, 제공자(Solar 직접 / BizRouter / Timely 통합 라우터), 프롬프트 스토어·버전, 추론 강도, System Prompt.
- **8. 검증 · 평가** · Groundedness(선택), ROUGE·어절 유사도, 정확도 게이트(§6.4 0.85), 샘플 검수, 테스트셋(1·2차).
- **9. 실행 · 리포트** · 단건(이미지/텍스트)·일괄(엑셀, 최대 200행) 실행, 통합 HTML 리포트, CSV/JSON 내보내기.

### 1.3 데이터 엔티티 (개념 모델)

| 엔티티 | 핵심 필드 | 상태 |
| --- | --- | --- |
| `Content` | displayServiceName · title · subtitle · body (이미지는 시각 신호 합성) | ✅ |
| `QualityMeta` | 법령 status(13종) · 품질 status · finalGrade(G/R) | 🟣 |
| `ItemMeta` | summary · entities · intent · content_category · topic · topic_categories | ✅ |
| `Topic` | type(엔티티/사건/조건) · members · topic_category | 🟣 |
| `UserMeta` | form · intensity(저·중·고) · pref_intent · pref_entity · pref_category | ⬜ |
| `Dictionary` | intent[] · content_category(Tier1/2) · 트롬↔IAB 매핑 | 🟣 |
| `Run`/`Report` | content_track · source · usage · grade · 집계 | ✅ |

### 1.4 인터페이스 (현재 구현)

- HTTP · `/run` `/run-batch` `/config` `/ping` `/models` `/vocab` `/template.csv` `/report` `/vendor/*`
- 키 · `~/.prism_key`(Solar) · `~/.prism_bizrouter_key` · `~/.prism_timely_key` (config.json 은 키 제외)

## 2. 풀스펙 로드맵

운영 경량화(품질 검수 자동화) + 맥락형 메타로 추천 품질 향상이라는 131 목표를 향해 4단계로 확장한다.

### P0 · 현재 (구현 완료)

- 아이템 메타 생성(텍스트 3필드 → 리드문·엔티티·인텐트·콘텐츠 카테고리)
- 이미지형 PoC · 시각 이해(Upstage Information Extraction / 라우터 멀티모달) → 메타
- 모델 라우팅 · 텍스트/이미지 슬롯 × Solar·BizRouter·Timely, model id 기반 자동 경로
- 로컬 어드민 UI(3분할 콘솔, Atelier식 설정 2탭), 엑셀 일괄, 통합 리포트, 패키징
- 품질·법령 프롬프트 골격, 검증·집계 골격(verify)

### P1 · 품질 게이팅 완성 + 사전 정합 (단기)

> 목표 · 유통 판정을 어드민에서 신뢰 가능하게 자동화하고, 사전을 자사 기준으로 고정.

- 품질 메타 2단계 완성 · 1차 법령(세트 구성·A·B·C 스코어링·RED 임계) ∥ 2차 품질(정의·status), status 종합 → G/R 유통 판정 화면
- 콘텐츠 카테고리 사전화 · 자유 생성 → 자사 사전(21 Tier1 + Custom Tier2), 트롬↔카테고리 매핑
- 인텐트 사전 운영 UI(서비스 그룹별)
- 엔티티 정제 · 인용 출처 vs 핵심 주체 규칙, 품질 균일화 필터
- 평가 체계 · ROUGE·어절 유사도, 정확도 게이트(0.85), 샘플 검수, 테스트셋(1·2차)
- 대시보드 v1 · 유통률·인텐트 분포·품질 지표
- 완료 기준 · 게이트 통과율·리드문 정확도 목표 충족, 사전 외 값 생성 0

### P2 · 토픽 빌더 + 운영 확장 (중기)

> 목표 · 단건 메타를 넘어 사안(토픽) 단위 묶음과 다양한 ITEM TYPE을 처리.

- 토픽(132) · 엔티티형·사건형(대표 1+관련 N, 중복 제거)·조건형(관심사×소비 방식) 빌더 + 클러스터 운영
- ITEM TYPE 분기 · 영상/SNS/묶음/데이터형 처리 정책, 출처 분류(PGC·UGC·AIGC·AIEC, C2PA·SynthID)
- 네이티브 이미지 트랙(방식 B) · image_only 전용 메타 에이전트
- 프롬프트 스토어/버전 운영 + 파인튜닝 파이프라인 연계(2차 품질 자동화)
- 운영 하드닝 · 동시성·레이트리밋·비용/지연 최적화(배치·캐시)
- 완료 기준 · 토픽 자동 생성·드릴다운 동작, 신규 ITEM TYPE 분류율 목표 충족

### P3 · 사용자 메타 + 활용처 (중장기)

> 목표 · 콘텐츠 측 맥락과 정합되는 사용자 측 맥락을 채워 "토픽×맥락×강도" 매칭.

- 사용자 메타(133) · TIARA 로그 → 세션화 → 소비 형태·강도·선호(동일 사전·척도)
- 콘텐츠×사용자 매칭 · 선호 인텐트∩콘텐츠 인텐트 + 강도 일치 + 카테고리 일치
- 활용처 연계 · 마이 스테이션·AI 에이전트·광고 타겟팅(IAB v3.0), 능동형 컴포넌트(조건형 토픽)
- 선결 과제 · 교차 서비스 동일인 식별, 형태 피처 표준화(TIARA 액션 타입), 개인정보·동의
- 전사 운영 대시보드 · 세그먼트(형태·강도)별 CTR·체류 모니터링
- 완료 기준 · 개인화 재배치 후 고강도 소비 비율·개인화 CTR 상승

### 의존성 · 정합 포인트

- 인텐트·콘텐츠 카테고리 **사전은 콘텐츠 측과 사용자 측이 공유**(P1에서 고정 → P3 매칭 전제)
- 품질 게이팅(P1) 통과분만 아이템 메타 → 토픽(P2) → 사용자 매칭(P3)
- 모델 라우팅·프롬프트 스토어(P0/P1)는 전 단계 공통 기반
- SPRINT 1·2 운영 단위는 각 페이지(131·133)의 진행 계획과 맞춘다
