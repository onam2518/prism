# 이미지 메타 추출 설계 (인텐트 판정 연결)

작성 2026-08-03 · **설계만 · 구현 계획 없음**

인입된 콘텐츠의 이미지 URL 을 비전 모델로 읽어 **사진 메타**를 뽑고, 그 메타를
아이템 메타 ③ 인텐트 판정에 넘기기 위한 설계다. 착수 시점이 정해지면 이 문서를
출발점으로 삼는다.

배경: 운영파트가 2026-08-03 인텐트 `포토·영상 중심` 기준을 합의했는데(직접 촬영 ·
현장 취재 · 사진 퀄리티), 그 판별에 필요한 신호가 파이프라인에 없다.
텍스트 쪽 대응은 PR #376 으로 반영했고, 남은 것이 이미지 쪽이다.

## 1. 지금 무엇이 있고 무엇이 없나

### 있는 것

| 부품 | 위치 | 상태 |
| --- | --- | --- |
| 비전 호출(멀티모달) | `prism/imagext.py:311-371 extract_signals` | 동작 · 장당 1호출 |
| 비전 스키마 4필드 | `prism/imagext.py:27-51 _VISION_SCHEMA` | `description`·`visible_text`·`entities`·`scene` |

| 장수 상한 | `imagext.py:59 MAX_IMAGES = 8` | 비전 호출 **전** 적용 |
| 키 부재 대응 | `imagext.py:289-295 _mock_signal` | 결정론적 자리표시자 |
| 이미지 URL 필드 | `prism/schema.py` `image_urls` · `normalize_image_urls` | http(s)만 · 중복 제거 · 상한 8 |
| URL 인입 보존 | PR #378 | 재실행 유실 수정 완료 · 다음 인입분부터 값이 남음 |
| 인텐트 콜 입력 | `prism/meta_prompts.py call_user` | PR #376 으로 제목·글자수·이미지 수까지 확장 |

### 없는 것 (이 설계가 채울 것)

- **URL 을 받아 이미지 바이트를 가져오는 경로.** `imagext` 는 업로드된 바이트만 받는다.
  URL fetch 코드는 저장소에 없다.
- **사진 종류·촬영 주체·품질을 묻는 스키마 항목.** 현재 4필드로는 "현장 사진인지
  그래픽인지 프로필 사진인지"를 구조화해 받을 수 없다.
- **추출 결과를 저장하는 자리.** `results`(sqlite)·`prism_contents`(supabase) 어디에도
  이미지 메타 컬럼이 없다.
- **인텐트 판정으로 넘기는 배선.** `call_user` 의 intent 분기에 이미지 메타 항이 없다.
- **비전 호출의 비용 계상.** `imagext` 는 `urllib` 직행이라 `trace.cost_usd` 원장에
  잡히지 않는다(`prism/dashops.py` 가 읽는 트레이스는 텍스트 파이프라인 산출물).
  현재도 이미 원장 밖이며, 인입 전 건으로 확대하면 이 공백이 그대로 커진다.

## 2. 설계 원칙

- **인입 시 1회 추출 · 저장.** 판정할 때마다 다시 부르지 않는다. 재실행·모델 A/B 는
  저장된 메타를 재사용한다. 비용이 실행 횟수에 곱해지면 안 된다.
- **"정보 없음"과 "0장"을 구분한다.** PR #376 에서 인텐트 프롬프트에 세운 원칙을
  이미지 메타에도 그대로 적용한다. 추출 실패·미실행을 "사진 없음"으로 읽히게 하면
  미부여 쪽으로 편향된다.
- **없는 정보를 추론시키지 않는다.** 비전이 못 본 항목은 빈 값으로 두고, 프롬프트는
  "근거가 없으면 부여하지 않는다"는 기존 원칙(`meta_prompts.py`)에 맡긴다.
- **의존성 0 유지.** `urllib`·`json`·`base64` 등 표준 라이브러리만. 이미지 디코딩
  라이브러리를 새로 들이지 않는다.
- **끌 수 있어야 한다.** 기본 꺼짐으로 시작해 표본으로 비용·품질을 재고 켠다.
- **기존 텍스트 경로를 건드리지 않는다.** 이미지 메타가 없어도 인텐트 판정은 지금대로
  동작해야 한다.

## 3. 데이터 흐름

```
인입 (엑셀 · 단건 · 자동)
   └ Content.image_urls  (schema.normalize_image_urls · http(s) · 중복제거 · 상한)
        │
        ├── [신규] 이미지 메타 추출 단계 (인입 직후 · 1회 · 비동기 가능)
        │      1. URL fetch          ← 신규 (안전 규칙은 §6)
        │      2. 장수 선별           ← 대표 1장 + 최대 N장
        │      3. 비전 호출           ← imagext.extract_signals 확장 스키마
        │      4. 집계               ← 장별 결과를 콘텐츠 1건 요약으로
        │      5. 저장               ← image_meta (§5)
        │
        └── 추출 파이프라인 (기존)
               ① 리드문 → ② 엔티티 → ③ 인텐트 → ④ 카테고리
                                     ↑
                        [신규] image_meta 요약 주입 (§7)
```

추출 단계는 **파이프라인 바깥**에 둔다. `harness` 스테이지로 넣으면 실행마다 돌고,
실패가 아이템 메타 산출을 막는다. 인입 후처리로 분리하면 실패해도 기존 판정이
그대로 진행되고, 나중에 백필도 같은 함수로 돌릴 수 있다.

## 4. 비전 스키마 확장

`imagext._VISION_SCHEMA` 에 아래를 추가한다. 기존 4필드는 유지한다(본문 합성 경로가
그대로 쓴다).

| 항목 | 형 | 설명 | 무엇을 푸는가 |
| --- | --- | --- | --- |
| `image_kind` | enum | `현장사진` `인물사진` `프로필사진` `그래픽·도표` `스크린샷` `스톡·자료사진` `AI생성` `기타` | 그래픽 vs 현장 구분 · 프로필 썸네일 미부여 |
| `credit_text` | string | 이미지에 **번인된** 출처 표기 원문. 없으면 빈 값 | 직접 촬영 판별의 1차 단서 |
| `ai_generated` | enum | `yes` `no` `unknown` | 생성형 AI 이미지만 있는 경우 미부여 |
| `quality` | enum | `high` `mid` `low` `unknown` | 저퀄리티 미부여 |
| `people_count` | enum | `0` `1` `few` `many` `unknown` | 프로필사진(1인 흉상) 판별 보조 |

설계 판단:

- **`credit_text` 를 위한 별도 크레딧 파서를 만들지 않는다.** 번인된 `ⓒ연합뉴스` 류는
  이미 `visible_text` 로 읽히고 있다. 전용 항목으로 분리해 받으면 정규식 사전을
  유지보수할 필요가 없다.
- **enum 은 열어 두지 말고 고정한다.** 자유 문자열로 받으면 표기가 흔들려 집계가 깨진다.
  `unknown` 을 명시적으로 두어 "모름"과 "해당 없음"을 구분한다.
- **"직접 촬영 여부"를 직접 묻지 않는다.** 모델이 사진만 보고 판단할 수 없는 항목이다.
  `image_kind` + `credit_text` + 본문 취재 정황을 조합해 프롬프트에서 판정한다.
- 본문 하단 텍스트 크레딧(`○○ 제공`)은 이미지가 아니라 본문에 있다. 이번 범위 밖이며,
  필요하면 별도 과제로 본문 파싱을 검토한다.

프롬프트 길이가 늘어 IE 응답이 불안정해지면, 기존 4필드 호출과 신규 5항목 호출을
분리하지 말고 **모델 교체**(라우터 멀티모달)를 먼저 검토한다. 순수 사진에서는 이미
라우터 폴백이 IE 보다 크게 낫다는 측정이 있다.

## 5. 저장

콘텐츠 1건당 이미지 메타 1개를 붙인다.

```jsonc
{
  "n_images": 4,              // 인입된 URL 개수 (분석한 장수와 다를 수 있음)
  "n_analyzed": 3,            // 실제 비전을 태운 장수
  "kinds": ["현장사진", "현장사진", "그래픽·도표"],
  "lead_kind": "현장사진",     // 대표(첫 장) 종류
  "credits": ["ⓒ연합뉴스"],    // 번인 크레딧 원문 (중복 제거)
  "ai_generated": "no",       // 전 장 집계 (하나라도 yes 면 판단 보류)
  "quality": "high",          // 대표 장 기준
  "people": "few",
  "status": "ok",             // ok | partial | failed | skipped | disabled
  "note": "",                 // 실패·부분 성공 사유
  "model": "…", "ts": 0
}
```

- `status` 를 반드시 남긴다. 값이 비었을 때 "사진이 없어서"인지 "못 읽어서"인지
  구분하지 못하면 §2 원칙이 깨진다.
- `n_images` 와 `n_analyzed` 를 나눈다. 상한 때문에 3장만 봤다는 사실이 드러나야 한다.

**저장 위치**: sqlite `results` 에 컬럼을 추가하는 기존 마이그레이션 패턴
(`store.py` 의 `ALTER TABLE … ADD COLUMN`)을 따른다.

**Supabase 주의**: DDL 은 코드로 적용되지 않는다(대시보드에서 수동). 컬럼을 보내는
코드가 먼저 배포되면 DDL 적용 전까지 `prism_contents` upsert 가 전량 실패한다
(PGRST204). PR #374 에서 같은 이유로 새 컬럼을 피한 선례가 있다. 둘 중 하나를 택한다:

- (A) `SUPABASE_MIGRATION.md` 에 DDL 을 먼저 문서화 → **수동 적용 확인 후** 코드 배포
- (B) 기존 JSON 컬럼 안에 넣어 DDL 없이 시작하고, 조회 요건이 생기면 컬럼으로 승격

초기에는 (B)가 배포 순서 사고를 원천 차단해 안전하다.

## 6. URL fetch 안전 규칙

외부 URL 을 서버가 직접 가져오는 것은 이 저장소에 처음 들어오는 동작이다.
아래를 지키지 않으면 SSRF·자원 고갈 경로가 된다.

- **스킴 제한**: http/https 만. `schema.normalize_image_urls` 가 이미 거른다.
- **사설 대역 차단**: 로컬호스트·사설 IP·링크로컬(`127.0.0.0/8`, `10/8`, `172.16/12`,
  `192.168/16`, `169.254/16`, `::1`, `fc00::/7`)로 해석되는 호스트 거부.
  리다이렉트 후 주소도 재검사한다.
- **크기 상한**: 응답을 통째로 읽지 말고 상한(예: 8MB)까지만 읽고 초과 시 중단.
- **타임아웃**: 연결·읽기 모두 짧게(예: 5초). 인입 배치를 붙잡으면 안 된다.
- **동시성 상한**: 한 배치가 외부 호스트를 두드리는 속도를 제한한다.
- **Content-Type 확인**: 이미지가 아니면 버린다.
- **실패는 조용히 넘기지 않는다**: `status`·`note` 에 남긴다.

## 7. 인텐트 판정으로 전달

`meta_prompts.call_user` 의 intent 분기에 한 줄 요약을 추가한다. 원본 JSON 을 통째로
넣지 않는다 — 인텐트는 전 아이템 필수 호출이라 토큰이 배치에 곱해진다.

```
이미지: 4장(분석 3장) · 대표=현장사진 · 종류=현장사진2·그래픽1 · 크레딧=ⓒ연합뉴스 · AI생성=아니오 · 품질=상
```

메타가 없을 때는 값을 지어내지 말고 현행 표기를 유지한다.

```
이미지: 정보 없음(입력에 이미지 목록이 없음 · '이미지가 0장'이라는 뜻이 아니다)
```

`CALL_RULES["intent"]` 의 `포토·영상 중심` 항에 해석 규칙을 덧붙인다. 이때
**정량 기준(몇 장 이상)을 다시 들이지 않는다** — 운영 합의의 첫 번째 조건이고,
`tests/test_prompt_policy.py` 가 장수 범위 표기 재유입을 막는다.

방향은 다음과 같다.

- 대표가 `프로필사진` 이고 다른 사진이 없으면 미부여
- 전 장이 `AI생성` 이면 미부여
- `그래픽·도표` 가 섞여 있어도 `현장사진` 이 있고 본문이 취재 기반이면 부여
- `품질=low` 이면 부여하지 않음
- 크레딧이 통신사·스톡 표기 일색이고 취재 정황 서술이 없으면 부여하지 않음
- 메타가 `정보 없음` 이면 **그것만을 이유로 미부여하지 않는다**

## 8. 비용

현 구조는 **장당 1호출**이다(`imagext.py:327` 루프). 최악의 경우 장당 IE 1 +
라우터 폴백 1 + OCR 1 = 3호출까지 간다. 영상 트랙(`mediaext.py`)은 반대로 프레임
8장을 1호출에 묶는다 — 이미지 쪽도 같은 방식을 검토할 여지가 있다.

착수 시 함께 처리할 것:

- **비전 호출을 비용 원장에 편입.** 지금은 `latency_ms` 만 기록하고 토큰·비용을
  산출하지 않아 얼마 쓰는지 보이지 않는다. 확대 전에 계측이 먼저다.
- **분석 장수 상한을 별도로 둔다.** `MAX_IMAGES=8` 은 업로드 경로용이다.
  URL 경로는 **대표 1장 + 최대 3장**으로 시작한다. 화보·현장 판별은 대표 1장이
  대부분 결정적이고, 장수를 늘리는 것은 측정 후 판단한다.
- **스위치와 표본.** 기본 꺼짐 → 표본으로 비용·정확도 측정 → 켠다.
- **배치 예산 상한과의 관계.** 현재 `runops` 의 배치 예산은 텍스트 실행 전용이라
  이미지 경로에 걸리지 않는다. 원장 편입과 같이 정리한다.

| --- | --- | --- |
| 0 | 인입 URL 실태 확인 | PR #378 배포 후 `image_urls` 가 실제로 채워지는지 · 채워지지 않으면 상류 협의부터 |
| 1 | 비전 호출 비용 계상 | 원장에 이미지 항목이 잡힘 |

단계 0 이 선행 조건이다. URL 이 안 들어오면 나머지는 전부 무의미하다.

## 10. 미결정

- **분석 장수.** 대표 1 + 3 은 제안값이며 측정 근거가 없다. 단계 2 에서 정한다.
- **모델 선택.** Upstage IE 는 문서·도표에 강하고 순수 사진에 약하다는 측정이 있다
  (2026-07-22 샘플 20장 · IE 0/20 vs 라우터 20/20). 확장 스키마에서도 같은 경향인지
  재측정이 필요하다.
- **본문 텍스트 크레딧(`○○ 제공`) 파싱 여부.** 이번 범위 밖으로 두었다.
- **영상 트랙과의 통합.** `mediaext` 의 프레임 묶음 호출 방식을 이미지에도 적용할지.
- **`mediaext` 의 `language` 값.** 현재 `merge_tracks` 반환에서 누락돼 버려진다.
  언어 메타를 도입하면 영상 트랙 언어 원천으로 재활용 가능하다.
- **기존 400건 백필.** 이미지 URL 이 이미 지워져 소급 복구가 안 된다. 원본 재수집이
  필요하면 별도 과제다.
