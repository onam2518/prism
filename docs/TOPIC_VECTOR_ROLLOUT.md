# 뉴스 토픽 의미순 샘플 조회

토픽의 명시적 메타·원본 조건을 통과한 뉴스 중 입력 의미에 가까운 샘플 5건을 표시하는 첫 적용 범위. 조건의 전체 매칭 건수·저장 정의·토픽 ID·운영 상태·개별 제외는 기존 계약 유지.

- 원본과 메타: 기존 Supabase 저장소.
- 조회용 인덱스: Qdrant `prism-topic-vectors`, 도쿄 512MB 머신·1GB 영속 볼륨, 공개 포트 없음.
- 임베딩: 기존 Solar query·passage 모델. 원문 제목·부제·본문 앞 6,000자 사용, 버전 식별은 전체 원문 해시 사용.
- 범위: 현재 유효 메타·유통 제한 검사를 통과한 `displayServiceName=뉴스` 콘텐츠. 서비스 표시는 탐색의 초기 범위이며 주제 카테고리로 추정하지 않음.
- 팀과 현재 조건을 통과한 콘텐츠 ID를 조회 필터로 전달하고 반환 ID도 다시 검사.
- 원문 수정·삭제·메타 변경 시 과거 벡터는 현재 허용 ID 목록에 포함되지 않으므로 결과에 노출되지 않음.
- 신규·수정 뉴스는 미리보기 조회에서 누락된 벡터가 확인되면 팀별 백그라운드 동기화. 조회용으로 선택되지 않은 오래된 벡터는 다음 정리 실행까지 보존 가능.
- 준비된 인덱스 일부만 조회했을 때는 범위와 준비 건수 표시. 장애 시 기본 샘플 유지와 장애 안내. 벡터 후보 수를 전체 매칭 건수로 표시 금지.
- 자연어 의미 확장·positive/negative 방식·자동 사건 병합·ContentFetcher는 이번 범위에 미포함.

## 최초 이관과 재실행

운영 머신에서 실행. 시크릿은 Fly 환경 변수 사용, 명령·로그에 키 값 기재 금지.

```sh
python -m prism.topicvectors --all-teams
```

완료 팀의 집계는 기존 `reports`의 `topic_vector_migration_v1`에 저장. 재실행은 현재 입력 해시·팀·모델로 발급한 점 ID를 조회하여 누락분만 추가. 새 Supabase 테이블이나 원본의 재추출은 없음.

```sh
python -m prism.topicvectors --all-teams --prune
```

정리 실행은 현재 조회 범위(팀별 최근 결과 최대 5,000행)에 없는 벡터를 제거하는 옵션. 원본·메타는 삭제하지 않지만 이 범위 밖의 오래된 뉴스도 벡터 재생성이 필요할 수 있으므로 운영 범위를 확인하고 실행.

## 확인과 복원

- 의미순 미리보기 응답의 `semantic`에 전체 조건 매칭 수·유효 뉴스 수·검색 준비 수·상태를 분리.
- 실제 연결 검증은 뉴스 벡터 이관 후 미리보기 결과의 현재 조건 충족과 팀 분리를 확인.
- 서비스 효과는 이후 실제 운영 문장으로 기존 샘플 대비 관련도·누락·지연을 평가. 배포 완료를 관련도 개선 실측으로 간주 금지.
- 기능 중지는 `PRISM_QDRANT_URL` 제거 후 기존 배포 절차 적용. 기존 매칭·저장 기능 사용 가능.
- 기존 DB·토픽을 덮어쓰지 않는 추가 인덱스 방식이라 원본 데이터의 역마이그레이션은 불필요.
- 인덱스 복구는 Fly 볼륨 스냅샷 또는 같은 모델로 위 이관 명령 재실행.
