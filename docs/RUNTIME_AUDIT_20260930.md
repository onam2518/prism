# 전체 코드 후속 검사 — 2026-09-30

PR #592 운영 반영 뒤 Python 모듈 71개와 자체 JavaScript 19개에 문법 검사를 적용하고, 저장·검수·학습·평가·토픽의 공통 메타 소비 경로를 추가로 추적했다. 모든 분기의 무결함이나 실제 운영 부하를 보증하는 검사는 아니다.

## 발견한 오류와 수정

- 객체형 카테고리를 문자열화하던 학습 커버리지·부족 분류·검수자 강점/담당 배정을 공통 표시 변환에 연결했다. 같은 Tier1의 여러 Tier2는 검수 배정 집계에서 한 번만 센다. 토픽 대표 분류에도 객체값이 그대로 문자열로 노출되지 않는다.
- 정답 원본 캐시에 요청한 해시 집합을 포함했다. 상세에서 한 건만 조회한 직후 전체 정답 후보를 조회하면, 기존 캐시가 나머지 후보를 누락시키던 문제를 막는다. 같은 집합의 순서·중복은 캐시 키를 늘리지 않으며 저장소 교체·쓰기 후 무효화도 유지한다.
- 사람이 명시적으로 확정한 빈 요약·빈 목록을 원래 모델 산출값으로 덮지 않는다. 정답에 해당 필드가 없을 때만 원본으로 표시를 보완한다.
- DNM 정답의 범위 선택·검수 조회·노하우 결합은 원천키/입력/정책 해시를 사용한다. 본문이 같은 다른 원천이나 일반 실험 콘텐츠의 검수 노트·교정 이력을 연결하지 않는다.
- 고정 평가의 후속 루브릭 채점은 평가 당시 입력 스냅샷을 사용한다. 현재 정답셋의 삭제·변경 때문에 채점이 누락되지 않고, 스냅샷 지문이 다르면 채점을 실패로 종료한다. 스냅샷 계약 도입 전 평가만 기존 정답셋 조회를 유지한다.

## 계산 비용 개선

`entconf.scored_entities`가 엔티티마다 같은 본문·제목·요약·이름 목록을 정규화하던 작업을 콘텐츠당 한 번으로 줄였다. 이름의 유니코드 정규화, 중복 이름의 최초 순위, 점수 산식과 표시 순서는 유지한다.

같은 로컬 환경에서 합성 콘텐츠 200건, 건당 엔티티 20개, 본문 13,600자로 각각 5회 측정한 중앙값:

계산 시간 약 92.4% 감소. 네트워크·DB·LLM 지연을 포함한 서비스 전체 응답시간 개선율이 아니다. 재현은 `python3 scripts/benchmark_entity_scoring.py`; 이전 체크아웃에는 `--repo <경로>`를 지정한다.
