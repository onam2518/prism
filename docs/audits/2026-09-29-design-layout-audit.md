# Prism 배치·정렬 점검 및 수정 소요

후속: [공통 컴포넌트 구현·검증 결과](2026-09-29-design-layout-implementation.md). 아래 내용은 수정 전 진단과 최초 견적을 보존한 기록이다.

점검일: 2026-09-29. 기준: 로컬 HEAD `28dd5c8` 및 현재 미커밋 UI. 세 담당자가 공통 CSS, 평가·비교, 기타 운영 화면을 병렬 검토했다. 원격 최신 main 전체를 점검한 결과는 아니다. 기존 사용자 변경은 수정하지 않았다.

## 범위와 증거 수준

- 사용자 제공 화면의 시각 확인, `prism/ui` HTML 조각 25개와 관련 공통 CSS·비교창 정적 점검.
- 정적 정의 기준 `.ds-table` 49개/13파일, `.filterbar` 11개/8파일, `.tiles` 7개/4파일. 동시 노출 화면·표 수가 아니다.
- 패널 조상을 식별한 표 44개 중 본문 `.panel-bd` 안 28개, 그 밖 16개. 전부 결함이라는 뜻은 아니다.
- 브라우저 런타임 연결 실패로 전체 화면의 실제 좌표·잘림·동적 상태는 검증하지 못했다. 아래 CSS 계산과 이미지 픽셀 추정은 DOM 실측과 구별한다.
- PR #534의 비교창 반응형 구현을 확인했다. #534–537은 기존 UI 작업과 파일이 겹치므로 구현 착수 전에 통합 기준을 정해야 한다.

## 발견 사항

### D1. 표 외곽과 상단 조작 영역의 좌우 경계 불일치 — 높음, 원인 확인

첨부 화면은 `prism/ui/13-eval.html:259` 모델별 비교 영역과 대응한다.

- `ds-theme.css:158–159`: 본문 여백 20px, 내부 여백 16px.
- `app.css:420`: `.panel-bd`에 좌우 20px padding.
- `app.css:53`: 모든 패널 하위 표 wrapper에 좌우 16px margin.
- `13-eval.html:261`: 선택기 영역은 inline margin으로 추가 좌우 여백 0.
- `13-eval.html:281`: 표 wrapper에는 추가 16px가 적용된다.

패널 안쪽을 원점, 너비를 W로 두면:

```
선택기 왼쪽 = 20
표 외곽 왼쪽 = 20 + 16 = 36
좌측 오차 = 16 CSS px
선택기 가용폭 = W - 40
표 wrapper 외곽폭 = W - 40 - 32 = W - 72
폭 차이 = 32 CSS px
```

이미지에서는 모델 영역 왼쪽 약137px, 표 왼쪽 약169px로 약32 이미지 픽셀 차이. 배율 2배라는 가정에 부합하나 실제 배율은 미확인이다. 잘린 이미지라 오른쪽 경계는 직접 확인할 수 없다.

표는 이미 `ds-components.css:238`에서 `width:100%`다. 따라서 표 너비 속성만 추가해도 부모 wrapper의 여백은 남는다. 본문이 좌우 여백을 소유하도록 정리하고, 본문 내부 표는 추가 좌우 여백을 제거하는 것이 핵심이다. 패널 직속 표는 별도 처리해야 한다.

평가 화면 표 9개는 모두 본문 내부에 있다. 일부는 tile padding까지 누적된다. 개체 사전·검수·crew 등에도 같은 구조가 있다. 외곽 정렬과 셀 내부 텍스트 padding은 별도 규칙으로 관리한다.

### D2. 표 배치 구조에 따른 정렬 규칙 중복 — D1에 포함

직속 표 외곽은 x=16, 본문 내부 표는 x=36이다. 같은 패널 너비에서 wrapper 폭 차이는 40px다. `app.css:960–963`은 직속 표 셀 padding을18px로 바꾸며, 일반 첫 셀은14px(`app.css:57`)다. 경계선1px를 더한 텍스트 시작점은 각각 약35px와51px다.

`app.css:957–958`의 18px 정렬 설명은 실제20px 제목 토큰과 맞지 않는다. 단일 여백 규칙과 설명을 함께 정리한다. 셀 텍스트를 패널 제목과 무조건 같은 선에 맞추는 것은 목표가 아니다.

### D3. 같은 작업줄의 입력·버튼 높이 불일치 — 중간, CSS 확인

`09-entdict.html:32–46`에서 기본 입력42px와 작은 버튼28px가 함께 놓인다. 중앙 정렬 시 위·아래 경계가 각각 `(42-28)/2=7px` 차이 난다. 필터바 입력36px와 중간 버튼34px도 존재한다(`app.css:169,277`).

크기 미지정 버튼은 `app.css:279`에 의해 최소36px다. 이 버튼에 inline `height:30px`만 설정해도 최소높이보다 작아지지 않는다. crew·콘텐츠·설정의 height 단독 지정은 실제 클래스와 함께 정리한다. DS 기본40px만 읽어 최종40px라고 판단하면 안 된다.

같은 줄에서 함께 조작하는 입력·선택·버튼은 같은 높이 변형을 사용한다. 표 안의 보조 액션처럼 역할이 다른 작은 버튼은 유지할 수 있다.

### D4. 고정 통계 열수와 좁은 화면 — 높음, 구조 확인·실제 잘림 미검증

- `09-entdict.html:18`: 6열 inline 정의가 공통 auto-fit 규칙을 덮는다.
- `ds-components.css:542`: 공통 카드 최소너비140px, 간격12px.
- 기존 최소너비를 유지하는 6열 패널 필요폭은 `6×140+5×12+2×20=940px` 이상(테두리는 별도).
- `app.css:470–471`: tile 간격10px, 좌우 padding32px, 테두리2px.
- n열에서 균등 분배를 가정한 내부 가용폭은 `(C-10(n-1))/n-34`. C=400px, n=4일 때58.5px다. min-content가 크면 이 폭으로 줄어드는 대신 넘칠 수 있다.
- `14-golden.html:36,343`의6열·5열과 평가4열도 점검 대상이다.

컨테이너 너비에 따라 열수를 줄이고 inline 열 정의를 공통 변형으로 통합한다. 사전·프롬프트 빌더의 고정2열도 함께 검증한다. 이미 반응형 전환이 있는 crewgrid·토픽 도움말은 재작성 대상에 넣지 않는다.

### D5. 모델 비교의 열 폭과 긴 이름 — 중간, 구조 확인

`13-eval.html:281–282`는 항목 열150px 외에 모델 열의 공통 폭 정책이 없다. `app.css:162`의 막대 최소160px와 셀 좌우 padding28px를 고려하면 모델 데이터 셀만 최소 약188n px다. 모델6개면1128px에 항목 열이 추가된다.

가로 스크롤 자체는 결함이 아니다. 모델 열의 일관된 최소폭, 긴 이름 줄바꿈, 항목 열 고정 여부를 정해 비교하기 쉬운 구조로 만든다. 화면 안에 강제로 모두 압축하지 않는다.

### D6. 패널 헤더 도구줄의 줄바꿈 — 중간, 실제 넘침 검증 필요

`app.css:310`의 패널 헤더는 flex지만 wrap이 없다. `07-studio.html:30–39`의 제목·설명·모드·상태, 콘텐츠 상단 도구줄은 작은 너비와 긴 상태 문구에서 점검해야 한다. 제목줄과 조작줄 분리 또는 명시적 wrap을 검토한다.

### D7. 작은 비교 진척도 창 — 기존 PR 재사용

현재 `compare-window.html:11`의4열 최소 고정폭은 `160+96+64+3×12=356px`다. 창·본문 좌우 여백80px와 패널 경계2px를 더하면438px 미만에서 고정 부분만으로 넘친다. 진행 막대의 최소폭은 추가된다.

PR #534에600px 이하 재배치가 이미 있다. 신규 구현이 아니라 해당 변경의 통합 및 검증으로 산정한다.

### D8. 팀 권한 표의 독립 규격 — 낮음

`15-team.html:94–109`는 공통 ds-table 대신 독립 표와8px 셀 padding을 사용한다. 공통 규격14px와의 차이가 의도적인 밀도 차이인지 확인하고 필요할 때 공통 compact 변형으로 통합한다.

## 수정 태스크와 공수

단위는 인시. 관측된 작업시간이 아닌 전문가 추정이다. 낙관 O / 대표 M / 비관 P를 제시하며, 화면별 반복을 공통 작업에 합쳐 중복을 제거했다. Q9가 전체 회귀 검증을 담당한다.

| 태스크 | 작업 | O | M | P | 선행 |
|---|---|---:|---:|---:|---|
| Q1 | 최신 기준·미커밋 변경·기존 UI PR 적용 범위 정리 | 1 | 2 | 3 | 없음 |
| Q2 | 패널·표 wrapper·첫 셀 규칙 통합(D1/D2) | 3 | 4 | 6 | Q1 |
| Q3 | 입력/버튼 높이 변형 정리(D3) | 2 | 3 | 4 | Q1 |
| Q4 | 통계·2열 레이아웃 반응형 통합(D4) | 3 | 4 | 6 | Q1 |
| Q5 | 모델 비교 열폭·긴 이름 처리(D5) | 2 | 3 | 5 | Q2 |
| Q6 | 복합 헤더 도구줄 재배치(D6) | 1 | 2 | 3 | Q1 |
| Q7 | 팀 권한 표 밀도 통합(D8) | 0.5 | 1 | 1.5 | Q2 |
| Q8 | #534 비교창 수정 통합·확인(D7) | 0.5 | 1 | 2 | Q1 |
| Q9 | 대표 화면·상태·반응형 회귀 검증 | 3 | 5 | 7 | Q2–Q8 |
| 합계 | | 16 | 25 | 37.5 | |

PERT 방식의 가중 대표값: `(16+4×25+37.5)/6=25.6인시`.
렌더 미검증·브랜치 통합 불확실성에 대한 계획 여유20%를 임의 가정하면 `25.6×1.2=30.7인시`, 약31인시다. 이는 통계적 신뢰구간이나 완료 보장이 아니다. 인시를 인원수로 나눈 값도 실제 경과시간을 보장하지 않는다.

첨부 사례만 국소 수정·확인하면1–2인시로 추정한다. 이 시간은 전체 계획의 Q2에 포함되므로 별도로 더하지 않는다. 공통 CSS 담당과 화면별 담당이 같은 파일을 수정할 수 있어, 병렬 구현 때는 소유 파일을 나누고 Q2 이후 Q5·Q7을 진행한다.

## 완료 판정 기준(제안)

- 같은 컨테이너의 필터와 표 **외곽** 좌·우 경계 차이 각각1 CSS px 이하. 서로 다른 의미의 영역에는 강제하지 않는다.
- 같은 역할의 작업줄 컨트롤 높이 편차1px 이하. 강조나 compact 변형은 명시한다.
- viewport1440/1280/1024/768 및 사이드바 분기900/901px 확인. 별도 비교창은600/438/375px 확인.
- 페이지 전체의 의도하지 않은 수평 넘침은0px. 데이터 표 내부의 의도한 가로 스크롤은 허용한다.
- 빈 목록/일반 데이터/긴 한국어·모델명/모델2개·6개/오류·진행 상태를 확인한다.
- 표49개 정의를 정적으로 확인하고 대표 유형별 렌더를 검사한다. 모든 상태 조합을 전수 검증한다는 의미는 아니다.
- 현재 미확인: 실제 DOM 좌표, 긴 데이터의 최종 줄바꿈, 색 대비·키보드 동작·모든 관리자 상태. 이를 이미 통과한 것으로 보고하지 않는다.

우선순위는 Q2 → Q3/Q4 → Q5/Q6 → Q7이며, Q8은 기존 PR을 재사용한다. 색상·글꼴을 전면 교체할 근거는 이번 점검에서 제시하지 않는다.
