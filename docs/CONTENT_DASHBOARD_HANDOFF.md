# 콘텐츠 대시보드(사용자향) · 서비스 설계 인수인계

스튜디오 메뉴에 추가할 **콘텐츠**(사용자향 대시보드)의 서비스 구성 인수인계 문서.
다른 세션/사람이 이어서 작업할 수 있도록 정의·흐름·구조·열린 결정을 정리한다.

- 상태: 서비스 구성 + 플로우 **와이어프레임 단계**(v0.4). 시각 디자인·실장 전.
- 산출물(화면): 와이어프레임 아티팩트
  `https://claude.ai/code/artifact/8394cdfb-6293-4522-9a40-de60aa3b1116`
- 와이어프레임 소스(저장소): `docs/content-service-wireframe.html`
- 참고: 이 서비스는 **어드민 도구가 아니라 사용자향**이라, 프리즘 관리자 UI 톤과 별개로 설계한다.

---

## 1. 한 줄 정의와 차별점

**내가 만든 뉴스 섹션 안에서 콘텐츠가 실시간 소비에 따라 자동으로 바뀌거나, 내가 직접 고정·편집하는 뉴스 대시보드.**

- 차별점: 뉴스봇 같은 **단순 콘텐츠 모음이 아니다.** 콘텐츠뿐 아니라 **컴포넌트(모듈) 구성까지 사용자가 조정·변경**한다.
- 즉 **메타로 구동되는 모듈형 구조**가 핵심 가치. (능동형 컴포넌트 생성 서비스)

## 2. 핵심 구조 (2단 + 메타)

```
뉴스 섹션 (적용 대상 · 컨테이너)
   └─ 컴포넌트 (콘텐츠 블록)
        ├─ 자동 : 요즘 소비 패턴에 맞춰 능동적으로 교체·정렬
        └─ 고정 : 사용자가 직접 편집·고정
```

- **섹션 만드는 재료 4축**: 분야(카테고리) · 주제(토픽) · 팔로우(엔티티) · 성격(깊게/빠르게/가볍게 = 인텐트).
- **컴포넌트 상태 2종**: 자동 / 고정. 한 섹션 안에 자동·고정이 섞인다.
- 품질 통과분(G)만 노출하되, **화면에는 품질 등급을 표기하지 않는다.**
- 사용자 화면 문구에는 내부 용어(메타/인텐트/페르소나/품질 G 등)를 쓰지 않는다. 쉬운 말로만.

## 3. 사용성 흐름 (3단계)

넷플릭스식 온보딩으로 시작해 빈 화면을 주지 않는 것이 원칙.

1. **온보딩 · 첫 섹션 만들기** (앱 우선 · 웹 동일)
   - 1-1 관심 분야 타일 다중 선택(최소 3개) → 첫 섹션 시드
   - 1-2 보는 방식(빠르게/깊게/가볍게) → 섹션 순서·카드 크기(성격)
   - 1-3 **대화형(챗봇)** 으로 관심 인물·주제 찾기 → 팔로우/주제 섹션 (건너뛰기 가능)
   - 1-4 완료 → 바로 채워진 대시보드로 진입
2. **대시보드 · 내 섹션들**
   - 웹 3분할(섹션 목록 · 피드 · "왜 보이는지" 근거) / 앱 카드 스택 + 가로 섹션 탭 + 하단 탭바
   - 컴포넌트에 자동/고정 배지. 근거는 "요즘 자주 봐서 올렸어요"처럼 쉬운 한 줄.
3. **조절 및 적용 · 2단 편집**
   - ① 섹션 레벨: 순서·켜기·추가 (적용 대상)
   - ② 컴포넌트 레벨: 섹션을 열어 자동↔고정 전환·빼기
   - 새 팔로우·주제·섹션 **추가는 대화형(챗봇)**
   - 웹=편집 화면(실시간 미리보기+적용) / 앱=바텀시트(완료)
   - **적용/완료 → 대시보드로 돌아가 갱신** (루프)

## 4. 대화형(챗봇) 인터페이스

- 엔티티(팔로우)·토픽(주제)을 **칩 목록으로 훑게 하지 않고**, 자유 문장으로 말하면 봇이 메타에서 후보를 찾아 "이렇게 만들까요?"로 제안 → 추가/생성.
- 적용 위치: 온보딩 1-3, 조절의 "섹션 추가".
- 예: "요즘 반도체랑 손흥민 경기 챙겨보고 싶어" → [손흥민·인물][반도체·주제][삼성전자·회사] 추가 제안.

## 5. 메타(재료) 출처 · 관련 코드

| 재료/신호 | 출처 | 파일 |
| --- | --- | --- |
| 분야(카테고리)·성격(인텐트)·엔티티 | 콘텐츠 추출 메타 | 파이프라인 / `dictops.py` `entdict.py` |
| 주제(토픽): 엔티티형·사건형·수동 | 토픽 체계 | `topicops.py` `topic.py` |

| 소비 형태·페르소나·"왜 떴는지" 근거 | 사용자 메타 | `usermeta.py` (시나리오: 형태 기반 재배치 · 능동형 컴포넌트 · 근거 설명) |
| 실시간 소비 신호(체류·클릭·완주) | 행동 로그 | `usermeta.py` 행동 로그 스펙 참고 |

## 6. 위치(스튜디오 편입)

- 스튜디오 메뉴는 현재 `prompt`·`topic` 2탭(opsadmin). 여기에 `content` 추가 예정.
  - 탭 상태: `prism/vendor/app-00-tabitems.js` 의 `studioTab`
  - 마크업: `prism/ui/07-studio.html`
- 단, 사용자향이므로 어드민 톤과 분리. **프로토타입은 독립 화면으로 먼저 만들고 흐름 확정 후 편입** 방식으로 진행 중.

## 7. 결정된 것 / 열린 것

**결정됨**
- 프로토타입(와이어 → 고화질) 먼저, 흐름 확정 후 스튜디오 이식.
- 재료 4축(분야·주제·팔로우·성격).
- 2단 모듈 구조(섹션 ⊃ 컴포넌트), 자동+고정 혼합.
- 관심사 찾기 = 대화형(챗봇).
- 사용성 순서: 온보딩 → 대시보드 → 조절·적용.
- PC(웹) + 모바일 앱 2버전.

**열린 것 (다음 세션 논의)**
- 온보딩 길이: 3스텝 유지 vs 2스텝 축소(성격 스텝 생략).
- 앱에서 조절 진입점: 하단 "정리" 탭 vs 상단 톱니(현재 하단 탭으로 그림).
- "왜 보이는지" 근거 노출 강도(크게 vs 은근히).
- **실시간 소비 신호 정의**: 무엇을 '소비'로 볼지(노출·클릭·체류·완주)와 자동 재배치 규칙.
- 컴포넌트 타입 확장: 카드 외 랭킹·요약·타임라인 등 모듈 종류.
- 최종 형태: 스튜디오 편입 vs 독립 사용자 서비스(별도 경로).
