# Prism 서비스 디자인 가이드

Prism(이미지 → 메타데이터 파이프라인)의 종합 서비스 디자인 가이드. **위젯 홈을 단일 중심**으로 한 위젯-기반 아키텍처를 정의한다.

> 이 문서가 최상위 가이드다. 세부는 링크로 위임한다 —
> 비주얼 `DESIGN.md` · 플로우 `PRINCIPLES.md` · 컴포넌트 구조 `COMPONENTS.md` · 산정/로드맵 `COMPONENT_ROADMAP.md`.

---

## 1. 철학

Perplexity의 "invisible brand · answer-first · calm over spectacle"를 Prism으로 옮기면:

- **결과(메타)가 주인공.** 크롬은 물러나고, teal은 액션·신호에만.
- **홈은 위젯 캔버스.** 사용자가 폰 홈처럼 **위젯을 골라 배치**해 자신의 작업대를 만든다. 고정된 대시보드를 강요하지 않는다.
- **위젯 = 자족 모듈.** 단순 디자인 단위가 아니라 **기능을 담은 단위**다. 추가·삭제·재배치·리사이즈가 일급 동작.
- **에이전트 메타포.** 파이프라인은 4명의 에이전트(다음프렌즈)가 협업하는 팀으로 표현된다.

핵심 화면은 **위젯 홈** 하나다. (초기 탐색본인 `dashboard.html`·`agent-dashboard.html`은 위젯 홈에 흡수되었으며 참고용으로만 남긴다.)

## 3. 정보구조 (IA) — 위젯 홈 중심

```
┌ 홈 (위젯 캔버스) ───────────────────────────────┐
│  [+추가] [편집] [테마]                            │
│  ┌기능 위젯┐ ┌기능 위젯┐ ┌정보 위젯┐ ┌정보 위젯┐  │
│  │새 배치  │ │사전 편집│ │오늘 현황│ │품질    │  │
│  └────────┘ └────────┘ └────────┘ └────────┘  │
│  ┌정보 위젯 ──────┐ ┌정보 ┐ ┌기능: 빠른 실행──┐  │
│  │실행 큐         │ │팀   │ │지시 입력 → 실행 │  │
│  └───────────────┘ └────┘ └────────────────┘  │
└────────────────────────────────────────────────┘
```

**좌측 사이드바 = 카테고리화된 위젯/도구 내비.** 모든 기능을 평면 나열하면 비효율적이라 **목적별 카테고리**로 묶는다. 각 항목은 세 타입 중 하나로 연결된다 — **워크스페이스**(위젯 조합으로 점프) · **단일 위젯**(위젯 하나로) · **전용 도구**(위젯화 불가 풀페이지).

```
홈                         위젯 캔버스 (고정)
── 작업 ──                 데이터를 만든다
   추출 실행      [워크스페이스]
   실행 큐        [단일 위젯]
── 산출 · 현황 ──          만든 메타를 본다
   배치 결과      [워크스페이스]
   품질 · 토픽    [단일 위젯]
   사용자 메타    [단일 위젯 · PoC]
   검증 · 평가    [워크스페이스 · PoC]
── 정책 · 기준 ──          기준을 정한다 (전용 도구·풀페이지)
   사전 · 정책 관리
   프롬프트 스튜디오
   인입 정책
── 하단 ──
   ⚙ 설정 · 온보딩  (팝업 — 사이드바 아님)
```

**카테고리 규칙**
- **작업** = 실행·생성. **산출·현황** = 만든 메타를 보는 정보 위젯/조합. **정책·기준** = 시스템 기준을 정하는 전용 도구(풀페이지). **설정** = 전역 구성, ⚙ 팝업으로 분리.
- 분류 기준: 위젯으로 완결되면 위젯, **풀스크린 편집·정책·긴 텍스트면 전용 도구**, 전역 설정만 ⚙ 팝업. (상세 분류 근거는 §10.1)

홈은 사용자가 꾸미는 캔버스, 사이드바는 **카테고리로 정리된 위젯/도구로의 빠른 이동**이다.

> 사이드바 디자인 = **하나의 고정 위젯처럼** 위젯 라운드 카드(`radius-xl` + surface + 헤어라인 + highlight)를 차용하고, **상단을 첫 위젯 시작과 정렬**한다(헤더는 풀폭 상단, 그 아래 사이드바·캔버스가 같은 행에서 시작).

## 4. 위젯 시스템 (핵심)

> **위젯 ≠ 축약.** 스마트폰 위젯은 앱의 요약/바로가기지만, **Prism 위젯은 그 위젯의 명명된 기능을 전부 수행하는 완결 단위(미니 앱)**다. "사전 편집" 위젯은 사전 편집의 전 과정을, "추출 실행" 위젯은 입력→실행→옵션을 위젯 안에서 끝낸다. 그래서 기능 위젯은 충분한 크기(보통 `lg`/`xl`)를 가진다.

### 4.0 배치 분류 — 고정 위젯 vs 캔버스 위젯

화면의 모든 영역은 "컴포넌트"가 아니라 **위젯**이다. 단 배치 방식이 둘로 나뉜다:

| 분류 | 위젯 | 편집 |
|---|---|---|
| **고정 위젯** | **상단 메뉴 위젯**(TopBar — 타이틀·도구) · **사이드 위젯**(사이드바 — 카테고리 내비) | **캔버스 편집 대상에서 제외**(지글·드래그·리사이즈 없음). 페이지 고정 크롬. |
| **캔버스 위젯** | 홈 그리드의 기능/정보 위젯 | 추가·삭제·재배치·리사이즈 **편집 가능** |

- 고정 위젯은 항상 같은 자리. 편집 모드를 켜도 흔들리지 않고, **스크롤해도 sticky로 제자리**를 지킨다.
- **사이드 위젯은 자체적으로 편집 가능**(항목 추가/정렬)할 수 있으나, 홈 캔버스의 위젯 편집과는 별개 모드다.

**레이아웃 규칙 (확정)**
```
[페이지 상단 여백 20px]
┌──────────────┬─────────────────────────────┐
│ 사이드 위젯    │ 상단 메뉴 위젯 (콘텐츠 폭)     │  ← 둘 다 라운드 카드, top 정렬, sticky
│ (라운드 카드)  ├─────────────────────────────┤
│              │ 캔버스 (편집 가능 위젯 bento)  │
│ ── 여백 ──   │                             │
│ 도우미        │                             │  ← 사이드 위젯 바로 밑에 부착(블랙 박스)
└──────────────┴─────────────────────────────┘
```
- **상단 메뉴 위젯**: 풀폭이 아니라 **콘텐츠 폭 라운드 카드**. `position: sticky` — 스크롤해도 제자리.
- **사이드 위젯**: 라운드 카드. top은 상단 메뉴 위젯과 정렬(같은 줄 시작).
- **둘 다 부드러운 그림자**로 살짝 떠 보이게(입체).
- **도우미**: 사이드 위젯 **바로 아래 부착**, 폭 동일. **다크 박스**(작업 상태 "작업 중 · N건 · 시간" + 캐릭터). 빈 컬럼 공간은 가상 영역(비표시).
- 정렬 원칙: 모든 위젯의 **상단 라인을 첫 컴포넌트와 맞춘다**(헤더만 따로 위에 뜨지 않게).

### 4.1 위젯 종류 (운영 구분)

| 종류 | 역할 | 예 | 표시 |
|---|---|---|---|
| **기능 위젯** | 특정 기능 **실행 + 메뉴** | 추출 실행, 사전 편집, 새 배치, 검수 시작 | 아이콘 칩(개성 컬러) + `기능` 칩 |
| **정보 위젯** | **정보 패널** | 오늘 한 일, 품질, 실행 큐, 활동, 프로세스, 담당 카드 | 중립 surface + `정보` 칩 |

- 기능 위젯 **메뉴형** = `LauncherWidget`(아이콘+제목+부제+chevron, 클릭→실행/이동).
- 기능 위젯 **실행형** = 입력·컨트롤을 위젯 안에 포함(예: 추출 실행 = Segmented+Dropzone+실행).
- 단, **대화형 실행 지시는 위젯이 아니라 하단 플로팅 도우미**로 분리한다(§4.6).

### 4.2 사이즈 규격 (4-col 셀)

폰 홈처럼 4-컬럼 셀 그리드에 스냅. **셀 단위로만** 배치·크기 변경(임의 픽셀 금지 → 정렬·반응형 보장).

| 토큰 | W×H | 용도 |
|---|---|---|
| `sm` | **1×1** | 단일 지표(오늘·품질) |
| `md` | **2×1** | 런처·큐·활동 |
| `lg` | **2×2** | 풀기능·리치 패널 |
| `tall` | **1×2** | 리스트(프로세스)·카드 |
| `wide` | **4×1** | 가로 띠 |
| `xl` | **4×2** | 대형 보드 |

### 4.3 배치 편집 (폰 홈 UX) — 최신

편집 모드에서:
- **점선 스냅 그리드** — 셀 코너 점으로 들어갈 자리 가시화.
- **삭제 X(우상단)만** 노출. *(사이즈 배지는 군더더기라 제거 — 크기는 선택 핸들로 조절.)*
- **선택 시** teal 링 + 8핸들, **우하단 핸들로 리사이즈**(셀 단위 순환).
- **지글 + 드래그 재배치 + 위젯 추가(팔레트)**.

### 4.4 위젯 디자인 원칙 (최신·중요)

1. **내부 스크롤 금지.** 내용이 많으면 스크롤 대신 **영역(크기)을 키운다**. 여백 최소·여유 유지.
2. **개성은 작은 신호로.** 아이콘 칩 컬러 + 따뜻한 타이틀("오늘"→"오늘 한 일"). **상단 라이닝 등 촌스러운 장식 금지.**
3. **캐릭터 요소 환영.** 단 **배경 투명 필수**(§7) — 컨테이너가 배경 책임, 캐릭터는 떠보이지 않게.
4. **설정은 위젯 아님.** 전역 설정은 헤더 ⚙ 팝업(§9.5).
5. **부드러운 입체감.** 위젯은 **미묘한 드롭섀도우 + 내부 하이라이트**로 살짝 떠 보이고, hover 시 2px 리프트. (과한 그림자 금지 — 절제된 입체.)
6. **런처는 컴팩트.** 메뉴형 기능 위젯(런처)은 팝업/플로우를 여는 **바로가기**이므로 큰 타일이 아니라 **자기 콘텐츠 높이**의 작은 가로 타일(`min-height:0`). 그리드 행은 내용 기반(auto).
7. **삭제는 ×(X).** 위젯 제거 버튼은 마이너스(−)가 아니라 ×. 편집 시 우상단에만 노출(사이즈 배지 없음).

### 4.5 위젯 카탈로그 (최신)

| 위젯 | 종류 | 크기 | 내부 |
|---|---|---|---|
| 추출 실행 | 기능(실행) | lg/xl | Segmented + FileDropzone + 썸네일 + CTA |
| 사전 편집 / 새 배치 / 검수 | 기능(런처) | md | LauncherWidget |
| 오늘 한 일 | 정보 | sm | Stat |
| 품질 | 정보 | sm | ProgressRing |
| 실행 큐 | 정보 | md | Run rows + ProgressBar |
| 방금 있었던 일 | 정보 | md | Activity feed |
| 프로세스 | 정보 | tall | 단계(추출·분석·검수·판정) + StatusDot |
| 담당 카드 | 정보 | tall | PersonaCard(홀로) |
| 배치 결과 / 단건 메타 / 토픽 / 사용자 메타 / 검증 | 정보(풀) | lg | StatGrid·Table·DefinitionList·GradePill 등 |

신규 위젯 = 이 표에 한 행 + `Widget`/`LauncherWidget` 조립. **확장은 위젯 단위.**

### 4.6 플로팅 도우미 + 작업 상태창 (기능 허브)

대화형 작업 지시는 위젯이 아니라 **화면 하단 플로팅 캐릭터**로 분리:
- **캐릭터만 크게**(원형 배경 없이, 드롭섀도우). 클릭 → 채팅 팝업(채널톡 스타일).
- 진행 중이면 캐릭터 위 **다크 작업 상태창**(스피너 + "작업 중 · N건 · 시간") — Now-brief 스타일.
- 채팅: 입력으로 지시 → 큐·활동 반영, 봇 응답.
- **모든 기능의 허브.** 빠른 작업 칩으로 기능을 **직접 실행**(예: 새 배치 추출 → 추출 모달, 설정 → 키 팝업)하고, 결과를 카드로 표시할 수 있다. 도우미 하나로 핵심 기능에 도달.

### 4.7 런처 = 실제 플로우

기능 위젯(런처)은 장식이 아니라 **실제 동작 진입점**이다. 클릭 시 그 기능의 완결 플로우를 연다:
- 예: **새 배치 추출** 런처 → 추출 모달(소스 Segmented + FileDropzone + 썸네일 + 추출 시작) → 실행 시 큐·활동·집계 갱신.
- 전용 도구 런처(사전·정책 관리 등) → 해당 전용 도구 페이지로 이동.

- **Primitive**: Button(pill·trailingIcon) · IconButton(+`[data-tip]` 툴팁) · Input/Composer · Select · Card · Badge(+메타칩) · Tabs · Table(rowActions) · Dialog · Toast · Toggle · Steps · AttachmentChip
- **Infographic**: Stat · ProgressBar/Distribution · ProgressRing · Skeleton · Spinner
- **App UI**: AppShell · Pane · Sidebar/NavItem · StatusDot · Segmented · KeyField · Accordion · FileDropzone · DefinitionList · GradePill · EmptyState · CodeBlock
- **Widget**: Widget(kind: 기능/정보) · WidgetGrid · LauncherWidget
- **Character**: Character · Persona · **PersonaCard(홀로 트레이딩 카드)** · Processing
- **안내·대화**: Coachmark(온보딩) · **Assistant(플로팅 도우미 + 작업 상태창)**

## 6. 프로세스 · 캐릭터 모델

Prism은 "에이전트"가 아니라 **데이터 추출·부여 프로세스**다. 그래서 **프로세스 단계로 명명**하고, 각 단계를 캐릭터가 의인화한다(딱딱함 방지).

| 단계 | 캐릭터 | 하는 일 |
|---|---|---|
| **추출** | 대식(블루) | 이미지 → 신호(OCR·비전) |
| **분석** | 용희(그린) | 메타 분류(엔티티·인텐트) |
| **검수** | 복실(화이트) | 품질 확인 |
| **판정 · 부여** | 딱지(레드) | 유통 결정(G/R) |

- `프로세스` 위젯에서 각 단계 상태(작업중/대기/유휴)를 StatusDot로.
- `PersonaCard`(홀로 카드)는 단계 담당 캐릭터를 카드로 — 포인터 3D 틸트 + 홀로 포일.
- **캐릭터는 장식이 아니라 톤.** 위젯·빈 상태·온보딩에 캐릭터를 얹어 "너무 딱딱하지 않게". 단 정보 밀도가 높은 패널은 절제.

### 6.1 위젯 개성 (타이틀·아이덴티티)

위젯은 균일한 회색 패널이 아니다. 각 위젯은:
- **개성 컬러**(`--w-accent`) — **아이콘 칩에만** 절제해서. 예: 오늘 `#2f6bff` · 품질 `#1f9d6b` · 프로세스 `#6e5a86` · 담당 카드 `#e0524a`. (상단 라이닝 같은 촌스러운 장식 금지.)
- **따뜻한 타이틀** — "오늘"이 아니라 "오늘 한 일", "활동"이 아니라 "방금 있었던 일", "빠른 실행"이 아니라 "지금 시작하기". 기능은 명확하게, 표현은 사람답게.
- 아이콘 칩(tinted square)으로 한눈에 구분.

> 원칙: 개성은 **작은 신호**(아이콘 칩·액센트·타이틀 톤)로. 본문·teal 시스템은 유지 — 화려함이 아니라 친근함.

---

## 7. 에셋 원칙 (캐릭터)

- **캐릭터는 배경 투명 필수.** Figma export의 프레임 배경(`<rect fill>`)은 제거. 배경/원형은 **감싸는 컨테이너**(아바타·카드 art)가 책임.
- 4색은 에이전트 구분 신호 — 리컬러 금지. 일러스트 영역(아바타·카드·빈 상태·처리)에만.
- 상세 → `PRINCIPLES.md §8`.

---

## 8. 모션 · 상태

- **모션**: fast 120 / standard 220 / slow 360ms, 커스텀 cubic-bezier. 페르소나 bob, foil, 스텝 펄스, 지글(편집), 스크롤 리빌. `prefers-reduced-motion` 전부 대응.
- **상태**: Empty(캐릭터+제안, 사과 없음) · Loading(Skeleton/Spinner) · Streaming(Steps 펄스) · Success(다크 Toast) · Error(error 보더+재시도) · Disabled(40%). → `PRINCIPLES.md §6`.

---

## 9. 접근성 · 군더더기 축소

- **아이콘 우선, 라벨은 호버.** 버튼·상태는 `IconButton` + `[data-tip]` 툴팁으로 시각 노이즈 축소. 단 `aria-label` 항상 유지.
- 포커스 링(teal), `role`/`aria-*`(switch·tab·dialog·progressbar), 키보드 동작 기본 제공.

---

## 9.5 온보딩 · 설정

위젯-홈은 생소한 개념이라 **첫 사용자 온보딩**이 필수다.

- **스텝바이스텝 코치마크** — 스포트라이트(`ds-coach-target`, 9999px 컷아웃) + 코치 카드(`Coachmark`). 단계: 환영 → 프로세스 → 위젯 추가 → 편집·배치 → 초기 설정.
- **캐릭터 가이드** — 각 스텝을 캐릭터가 안내(복실·대식·용희·딱지). 딱딱하지 않게.
- **실제 적용까지** — 마지막 스텝이 ⚙ 설정을 열어 **API 키 입력**으로 마무리. 보는 것에서 끝나지 않는다.
- **다시 보기** — 첫 방문 자동 실행(localStorage), 이후 **설정 > 온보딩 다시 보기**로 재생.

**설정은 위젯이 아니다.** API 키 등 초기/전역 설정은 위젯화하지 않고, **다크모드 버튼 옆 ⚙ 버튼 → 고정 팝업(Dialog)**으로 연다. (위젯은 반복 사용하는 기능·정보, 설정은 가끔 만지는 전역 구성 — 역할이 다르다.)

## 10. 확장성 · 거버넌스

1. **새 기능 = 새 위젯** (전용 화면보다 위젯 우선). 기능/정보 종류와 셀 규격을 지킨다.
2. **새 컴포넌트보다 기존 50+ 조합.** 추가 시 `COMPONENTS.md`에 6칸(해부·부품·API·variant·상태·금지) 먼저.
3. **단일 토큰 소스.** 색/간격/모션은 `tokens.json`·`theme.css`만 수정 → 전체 반영.
4. **원칙 우선순위:** 충돌 시 `PRINCIPLES.md`(단계 명확성·절제) > `DESIGN.md`(비주얼) > 외부 스킬(스펙터클).

### 10.1 배치 결정 — 위젯 vs 전용 도구 vs 팝업

새 기능을 어디에 둘지 결정하는 규칙(코드베이스 모듈 기준):

| 어디에 | 조건 | serve.py 모듈 |
|---|---|---|
| **위젯 (홈)** | 정보 조회 or 단일·소수 액션 · 셀 수용 · 반복 사용 | 추출 실행, 배치 결과, 단건 메타, 품질, 토픽, 사용자 메타, 검증(요약), 대시보드 |
| **사이드바 전용 도구 (풀페이지)** | ① 대량 편집·관리 ② 규칙·정책 작성 ③ 긴 텍스트(프롬프트) ④ 풀스크린 작업대 ⑤ 드문·위험 구성 | 사전·정책 관리(서비스그룹별·override), 프롬프트 스튜디오(systemPrompt·sync), 인입 정책(intake), 평가 워크벤치 |
| **헤더 ⚙ 팝업** | 전역/계정 설정 | API 키(Solar·BizRouter·Timely), 테마, 온보딩 |

> 한 줄: **위젯으로 완결되면 위젯 · 풀스크린 편집/정책/긴 텍스트면 전용 도구 · 전역 설정만 팝업.** 하이브리드(예: 사전)는 가벼운 편집=위젯, 깊은 관리=전용 도구로 쪼갠다.
