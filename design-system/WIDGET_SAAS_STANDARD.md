# 위젯형 SaaS — 표준 디자인 정책 · 가이드

> 위젯(widget)을 1급 단위로 삼는 SaaS 제품의 **표준 디자인 정책**. Prism(이미지→메타 파이프라인)을 레퍼런스 구현으로 일반화했다.
> 이 문서는 제품 비종속 표준이다. 제품별 적용은 토큰·카테고리·캐릭터만 갈아끼운다.

## 0. 철학 — 왜 위젯형인가

1. **화면의 모든 영역은 "컴포넌트"가 아니라 위젯이다.** 상단 바도, 사이드바도, 콘텐츠 카드도 위젯. 단 배치 방식이 다를 뿐.
2. **위젯 = 완결 단위(미니 앱).** 스마트폰 위젯이 앱의 요약/바로가기라면, **위젯형 SaaS의 위젯은 그 명명된 기능을 위젯 안에서 전부 수행**한다. (예외: 런처는 의도된 바로가기.)
3. **사용자가 홈을 조립한다.** 폰 홈 화면처럼 위젯을 추가·삭제·재배치·리사이즈해 자기 작업대를 만든다.
4. **확장은 위젯 단위.** 새 기능 = 새 위젯. 화면을 늘리지 않고 위젯을 늘린다.
5. **절제된 친근함.** 정보는 명확하게, 표현은 사람답게. 브랜드/캐릭터는 작은 신호로만.

<a id="1"></a>
## 1. 위젯 분류 체계 (2축)

### 축 A — 배치 (편집 가능 여부)
| 분류 | 정의 | 편집 |
|---|---|---|
| **고정 위젯** | 페이지 전역 크롬 (상단 메뉴 위젯 · 사이드 위젯) | 캔버스 편집 **제외** · sticky로 제자리 |
| **캔버스 위젯** | 홈 캔버스의 위젯 | 추가·삭제·재배치·리사이즈 **가능** |

### 축 B — 역할
| 분류 | 정의 | 표시 |
|---|---|---|
| **기능 위젯** | 특정 기능 실행/메뉴 | 아이콘 칩(개성 컬러) + `기능` 칩 |
| **정보 위젯** | 정보 패널(대시보드) | 중립 surface + `정보` 칩 |

- 기능 위젯 **메뉴형 = 런처**(아이콘+제목+부제+chevron). 클릭 → **실제 플로우**(모달/전용 페이지). 컴팩트.
- 기능 위젯 **실행형** = 입력·컨트롤을 위젯 안에 포함.
- **대화형 실행 지시**는 위젯이 아니라 **플로팅 도우미**로 분리(§2).

<a id="2"></a>
## 2. 레이아웃 표준

```
[페이지 상단 여백]
┌──────────────┬─────────────────────────────┐
│ 사이드 위젯    │ 상단 메뉴 위젯 (콘텐츠 폭)     │  둘 다 라운드 카드 · top 정렬 · sticky
│ (라운드 카드)  ├─────────────────────────────┤
│              │ 캔버스 (편집 가능 위젯 bento)  │
│ ── 여백 ──   │                             │
│ 도우미        │                             │  사이드 위젯 바로 밑 부착
└──────────────┴─────────────────────────────┘
```

**규칙**
1. **2-컬럼 그리드**(사이드 고정폭 · 콘텐츠 1fr), 상단 여백, 중앙 정렬 컨테이너.
2. **상단 메뉴 위젯** — 풀폭 아님. **콘텐츠 폭 라운드 카드**. `position: sticky` (스크롤해도 제자리). 타이틀(좌)+도구 아이콘(우), 수직 중앙, 좌우 대칭 패딩.
3. **사이드 위젯** — 라운드 카드. **top을 상단 메뉴 위젯과 정렬**(같은 줄 시작). 카테고리 구분선 + 라벨/항목 위계.
4. **정렬 원칙** — 모든 위젯의 **상단 라인을 첫 컴포넌트와 맞춘다**. 헤더만 따로 위에 뜨지 않게.
5. **도우미** — 사이드 위젯 **바로 아래 부착**(여백 확보), 폭 동일. 작업 상태(다크 박스: "작업 중 · N건 · 시간" + 캐릭터). 빈 컬럼은 **가상 영역(비표시)**.
6. **입체감** — 위젯/사이드/상단 위젯에 **부드러운 드롭섀도우 + 내부 하이라이트**. 캔버스 위젯 hover 시 미세 리프트(−2px). 과한 그림자 금지.

<a id="3"></a>
## 3. 위젯 규격 · 편집

### 사이즈 규격 (셀 그리드)
- 기본 캔버스 = **N 컬럼 셀 그리드**(예: 4). **셀 단위로만** 배치·리사이즈(임의 픽셀 금지 → 정렬·반응형 보장).
- 사이즈 카탈로그(W×H): `sm 1×1` · `md 2×1` · `lg 2×2` · `tall 1×2` · `wide N×1` · `xl N×2`.
- **행은 내용 기반(auto)**, 위젯은 `min-height`로 카드감 유지. **런처는 `min-height:0`(컴팩트)**.

### 편집 모드 (폰 홈 UX)
- **점선 스냅 그리드** — 셀 코너 점으로 배치 위치 가시화.
- **삭제 ×(우상단)만** 노출. 마이너스(−) 금지. **사이즈 배지 없음**.
- **선택** 시 링 + 8핸들(우하단 = 리사이즈).
- **지글 + 드래그 재배치 + 위젯 추가(팔레트)**.
- 고정 위젯(상단·사이드)은 **편집 제외**. 사이드 위젯의 항목 편집은 별개 모드.

<a id="4"></a>
## 4. 위젯 디자인 원칙

1. **내부 스크롤 금지.** 내용이 많으면 스크롤 대신 **영역(크기)을 키운다**. 여백 최소·여유 유지. (예외: 채팅 로그·코드 블록.)
2. **개성은 작은 신호로.** 아이콘 칩 컬러 + 따뜻한 타이틀("오늘"→"오늘 한 일"). **상단 라이닝 등 촌스러운 장식 금지.**
3. **부드러운 입체감.** 미묘한 그림자 + hover 리프트. 절제.
4. **브랜드/캐릭터 요소 환영, 단 절제.** 일러스트는 **배경 투명 필수**(컨테이너가 배경 책임, 떠보이지 않게). 정보 밀도 높은 패널은 자제.
5. **런처는 컴팩트.** 큰 타일이 아니라 자기 콘텐츠 높이의 바로가기.
6. **한 위젯 한 책임.** 한 위젯은 하나의 명명된 기능/정보. teal/포인트색은 액션·강조 신호로만.
7. **삭제는 ×.** 위젯 제거는 마이너스가 아니라 ×.

<a id="5"></a>
## 5. 내비 IA 표준 — 위젯 vs 전용 도구 vs 팝업

사이드바는 **카테고리화된 위젯/도구 내비**. 평면 나열 금지. 각 항목은 세 타입 중 하나:
- **워크스페이스** — 위젯 조합(여러 위젯 미리 배치)으로 점프.
- **단일 위젯** — 위젯 하나로 점프.
- **전용 도구** — 위젯화 불가 풀페이지로 이동.

### 어디에 둘지 결정 규칙
| 어디에 | 조건 |
|---|---|
| **위젯 (홈)** | 정보 조회 or 단일·소수 액션 · 셀 수용 · 반복 사용 |
| **사이드바 전용 도구(풀페이지)** | ① 대량 편집·관리 ② 규칙·정책 작성 ③ 긴 텍스트 편집 ④ 풀스크린 작업대 ⑤ 드문·위험 구성 |
| **헤더 ⚙ 팝업** | 전역/계정 설정(키·테마·온보딩 등) — **위젯 아님** |

> 한 줄: **위젯으로 완결되면 위젯 · 풀스크린 편집/정책/긴 텍스트면 전용 도구 · 전역 설정만 팝업.** 하이브리드는 가벼운 편집=위젯, 깊은 관리=전용 도구로 쪼갠다.

<a id="6"></a>
## 6. 토큰 표준

단일 소스(`tokens.json` → `theme.css` CSS 변수 → 컴포넌트). 색이 바뀌면 여기만 고친다.

| 그룹 | 표준 |
|---|---|
| **Primary** | 브랜드 단일 액센트 1색 (인터랙션·강조·인용에만, 장식 금지) + hover/deep/tint 변형 |
| **표면** | page(따뜻/중립, 순백 금지) · card · input/overlay white |
| **잉크** | near-black(=#000 금지) · body · muted · placeholder · hairline/soft |
| **다크** | 같은 토큰의 1급 모드(`.ds-dark`/`[data-theme=dark]`) — 별도 브랜드 아님 |
| **의미** | success · error · warning |
| **타이포** | UI 그로테스크 / 본문 가독체 / mono — 시스템 폴백 |
| **Radius** | sm·md·lg·xl(위젯)·2xl(히어로)·full |
| **Shadow** | 페이퍼-플랫 기본 + 위젯 elevation(ambient~modal 단계) + 내부 하이라이트 |
| **Motion** | fast 120 / standard 220 / slow 360ms · 커스텀 cubic-bezier · `prefers-reduced-motion` 대응 |

<a id="7"></a>
## 7. 컴포넌트 표준

위젯 내부를 채우는 빌딩블록. **새 컴포넌트보다 기존 조합 우선.** 네이밍 `ds-{c}` / `ds-{c}--{variant}` / `ds-{c}__{part}` / 상태는 `aria-*`.

권장 최소 셋:
- **Primitive**: Button(+pill) · IconButton(+호버 툴팁) · Input/Composer · Select · Card · Badge · Tabs · Table · Dialog · Toast · Toggle · Steps · AttachmentChip
- **Infographic**: Stat · ProgressBar/Distribution · ProgressRing · Skeleton · Spinner
- **App UI**: Sidebar/NavItem · StatusDot · Segmented · KeyField · Accordion · FileDropzone · DefinitionList · GradePill · EmptyState · CodeBlock
- **Widget**: Widget(kind 기능/정보) · WidgetGrid · LauncherWidget
- **안내·대화**: Coachmark(온보딩) · Assistant(플로팅 도우미)
- **브랜드**: Character · Persona/PersonaCard (제품별)

신규 컴포넌트는 **6칸(해부·부품·API·variant·상태·금지)**을 먼저 정의한 뒤 코드를 쓴다.

<a id="8"></a>
## 8. 상태 · 모션 표준

| 상태 | 처리 |
|---|---|
| Empty | 안내 한 줄 + 다음 행동(+캐릭터 옵션), 사과 없음 |
| Loading | Skeleton(최종 치수) / Spinner |
| Working/Streaming | Steps(단계 펄스) + 도우미 작업 상태창 |
| Success | 토스트(짧게) |
| Error | error 보더 인라인 + 재시도, 마스코트·"Oops" 없음 |
| Disabled | 40% 불투명, 지오메트리 유지 |

모션: 커스텀 cubic-bezier만. 위젯 hover 리프트·편집 지글·스크롤 리빌·캐릭터 bob 등은 **절제**. reduced-motion 전부 대응.

<a id="9"></a>
## 9. 접근성 표준

- **아이콘 우선, 라벨은 호버 툴팁**(`[data-tip]`)으로 군더더기 축소 — 단 `aria-label` 항상 유지.
- 포커스 링(브랜드색), `role`/`aria-*`(switch·tab·dialog·progressbar), 키보드 동작 기본.
- 색만으로 의미 전달 금지(아이콘/텍스트 병행). 대비 충족.

<a id="10"></a>
## 10. 온보딩 표준 (필수)

위젯-홈은 생소하다 → **첫 사용자 온보딩 필수**.
- **스텝바이스텝 코치마크**(스포트라이트 + 코치 카드) — 환영 → 위젯 추가 → 편집·배치 → 초기 설정.
- **마스코트/캐릭터 가이드**로 딱딱하지 않게.
- **실제 적용까지** — 마지막 스텝이 설정을 열어 초기 구성을 마무리. 보는 것에서 끝나지 않음.
- **다시 보기** — 첫 방문 자동(localStorage), 이후 설정에서 재생.

<a id="11"></a>
## 11. 거버넌스 · 확장

1. **새 기능 = 새 위젯** (전용 화면보다 위젯 우선). 종류(기능/정보)·셀 규격 준수.
2. **단일 토큰 소스** — 색/간격/모션은 토큰만 수정 → 전체 반영.
3. **새 컴포넌트보다 기존 조합.** 추가 시 6칸 정의 먼저.
4. **고정 위젯/캔버스 위젯 경계 유지** — 전역 크롬은 편집 제외.
5. **원칙 우선순위** — 플로우 원칙(명확·절제) > 비주얼 > 외부 트렌드/스킬.
